# 文件管理 v1.11.0

- 监控总开关改为立即保存，与规则编辑分开；可先开启，再选择目录。没有规则时显示“已开启，等待添加监控目录”，不扫描其他目录。
- 助手新增 Google Live Updates 待处理汇总通知与权限设置入口；支持 Android 16 及以上，显示待处理数量和当前文件，提供转移、保留原处及收起操作。
- 收起只隐藏当前批次实时更新，不处理或移动文件；不会在轮询或重启助手后反复弹回。新增文件仍可再次提醒。
- 普通文件通知和原有悬浮询问保留；系统不允许或不支持实时更新时仍可正常处理。
- 规则保存失败原因同时显示在保存按钮附近。
- 调整窄屏设置行布局：最小文件大小、等待时间与右侧选项保持同行；删除启动说明和手动重新读取配色入口，Monet 继续自动更新。
- 文件类型分组移除已选数量，支持全选、取消全选及逐项选择。
- 启动监控时提前请求助手提醒服务，助手尽早进入前台服务；唤起命令增加超时、失败检测及日志，读取状态超时会重试，避免长时间卡住。

本版在本地完成构建、自动化测试与多尺寸浏览器布局检查。按用户要求未在手机安装本版；后台提醒恢复及流体云胶囊效果仍需实机验证。流体云展示由系统资格判断和用户设置决定，不能仅凭 API 接入保证胶囊展示。

## v1.9.1 说明

助手新图标采用文件夹与转移箭头，自适应圆形和系统主题图标。文件类型全部展开，点击即可多选。

监控约每 2 秒扫描一次。新增 ZIP／APK（包括 APK.1、APKS、XAPK、APKM）在完整 ZIP 结构、所有条目 CRC 检查通过，且没有可观察的写入和临时下载记录时，直接进入询问，不再固定等 60 秒。仍在写入、大小或时间变化、损坏或下载不完整时继续等待。其他类型不能可靠确认完成，默认稳定 10 秒兜底，可在界面选择 5 秒至 5 分钟；旧固定等待配置升级为 10 秒兜底，不重建检测基准。

新待处理项立即唤起助手读取结果，原有待处理项每 30 秒尝试恢复提醒；助手定时检查改为 5 秒，并在收到唤起和解锁事件时立即检查。锁屏期间保留通知，解锁后再显示悬浮询问。CRC 检查和文件读取仍需要时间，下载器的特殊暂停、未暴露的写入或系统冻结可能影响判断与提醒，不能保证所有下载器的真实完成状态。ColorOS／冻结工具仍需允许助手后台运行。

当前未连接手机。本机测试、签名和浏览器验证见交付报告；不将这些结果视为 ColorOS 17 实机弹窗验证。

## 既有功能和构建说明

一个规则可选择多个监控目录，统一选择目标目录，并勾选单个或多个文件类型。助手内提供概览、监控、待处理、设置四页，与模块 WebUI 共用监控编辑组件。

旧规则自动兼容，不要求重新添加原目录。增加来源时只忽略新增目录内已有文件，原目录待处理项保留；仅删除来源时取消该来源未执行的提醒。类型、目标或递归设置变化时，沿用重新记录已有文件的行为。

助手的初次连接需要允许 Root。通知、悬浮窗和后台运行权限仍由用户设置；ColorOS／冻结工具需将助手放行。助手只加载自带页面，不提供外部网页访问；规则保存前检查模块版本匹配，避免新界面配合旧后端时丢失多目录设置。

本次按用户提供的 FileManagerV7.4.0 助手的卡片、状态与导航风格重新编写界面，没有复制或分发其 APK、后端程序或资源。

构建先运行 npm ci，再按下文配置签名与 SDK。v1.9.0 本机测试和浏览器预览通过，未进行手机实装验证。

# 文件管理

KernelSU／Magisk ARM64 文件工具，支持内容查重、文件名日期与双重后缀修复、回收站，以及新增文件转移询问。

## v1.8.0 使用

1. 安装完整 `FileManager-v1.8.0-arm64.zip`，刷新模块列表并关闭旧 WebUI 后重新打开，无需额外下载助手 APK。模块安装后会自动安装“文件管理助手”；若失败，在 WebUI 打开助手会失败，请查 `/data/adb/dupeguard/helper-install.log` 和 `helper-status`。
2. 进入“监控 → 设置提醒权限”。在助手中依次连接模块、手动允许 KernelSU Root 授权、通知和显示在其他应用上层。按 ColorOS 要求允许后台运行／自启动。权限由用户选择，模块不自动授予。
3. 返回 WebUI，添加监控目录和目标目录，输入后缀（默认 `.zip, .apk`），选择是否递归；勾选启用并保存。目标目录不能位于任何监控目录内。支持内部共享存储中现有的普通目录，沿用原有 Android／隐藏目录／符号链接排除规则。
4. 保存时对新建、变更、重新启用的规则建立已有文件基准；关闭期间的文件作为已有文件，不补发历史提醒。默认每 5 秒检查一次，最多 20 条规则、10 万个扫描文件，待处理队列最多 500 项；积压减少后再处理后续项。
5. ZIP／APK 持续稳定后检查 ZIP 结构和 CRC，并排除常见临时记录及能够观察到的写入句柄；无法保证识别所有下载器的真实完成状态。其他格式只依据稳定时间，应核对下载状态。加密、分卷或校验失败的压缩包可能一直等待；源文件改变会重新等待，不会立即移动。
6. 通知中可选转移／保留原处；有悬浮窗权限并解锁时显示原生询问。稍后处理的文件保持原处，WebUI 的待转移列表可继续处理。助手提醒默认开启，也可在助手中暂停；该开关不删除待处理记录。
7. 转移前后校验文件，目标同名拒绝覆盖。复制完成先保存记录，再删源；中断或删除失败可能保留两份，最近处理记录会提示核对，不会盲目重试覆盖。

## 数据与卸载

ID 为 `filemanager`，兼容保留私有目录 `/data/adb/dupeguard/`；监控配置、基准和历史也保存在此。回收站 `/storage/emulated/0/Android/FileManager/Trash/`。助手包名 `io.github.qisun8023.filemanager.helper`。

卸载将停止监控、清空回收站及私有记录，并在 APK 摘要与安装记录一致时卸载助手。源目录和已转移到目标目录的文件不删除。共享存储未解锁时保留既有延后清理逻辑；异常路径、活动任务或卸载失败会保留无法安全清理的记录。

旧 `dupeguard` 更新清单 `update.json` 固定 v1.6.0；新标识使用 `update-filemanager.json`。不能将两条渠道混用。v1.8.0 的发布附件未上传前，不得推进 main 的在线更新清单。

## 构建

需要 Python 3.10+、Go 1.24+、Node.js、Git Bash、JDK 17、Android SDK platform android-36 和 build-tools 36.1.0。助手 minSdk 29，targetSdk 36，可在更高系统运行，但 Android 17／ColorOS 17 需要实际验证；原查重功能仍以模块自身要求为准。

先运行 `npm ci` 安装界面验证依赖。配置 `ANDROID_SDK_ROOT`、`JAVA_HOME`，以及仓库外的持久签名文件 `FM_KEYSTORE`、密码文件 `FM_KEYPASS_FILE`。签名证书与密码必须备份，后续助手更新需要同一签名，绝不能提交到 GitHub 或放进源码 ZIP。`python tools/build_companion.py` 编译和签名助手；完整 `python tools/build.py --go <go路径> --bash <bash路径>` 测试并构建模块。版本工具同时同步助手 Manifest 版本。

源码包含 `engine/`、`module/`、`companion/`、`tests/`、`tools/` 和 Node 测试依赖清单；编译产物、依赖目录、签名私钥不提交。助手没有联网权限，公开入口仅为权限设置 Activity；文件操作来自用户点击并经模块校验。
