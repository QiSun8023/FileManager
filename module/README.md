# 文件管理 v1.7.1 · 新内部标识

本版内部 ID 为 filemanager，程序入口为 `/data/adb/modules/filemanager/bin/filemanager`。原 dupeguard 用户需要手动安装一次本迁移版本；停止任务、关闭旧网页后安装，不要先卸载旧模块。

新程序检查通过后才退休旧入口，并将旧模块目录保留在 `/data/adb/dupeguard/legacy-module-dupeguard`。私有记录仍复用 `/data/adb/dupeguard`，回收站和恢复记录路径不变。这样保留历史数据和共用操作锁，无需迁移数据内容。新标识后续更新从 update-filemanager.json 获取，旧标识渠道留在 v1.6.0。

本迁移包仅在已开机的管理器中安装。旧任务运行、待安装目录、身份/路径不符和备份冲突会阻止旧模块退休，原数据保留。新模块按 ID 隔离的网页偏好可能重置。新旧并存或状态异常时先检查安装日志，不要同时开启两个界面。

## 目录选择

扫描和文件修复页面点击文件夹路径框，直接弹出目录选择器。可以进入子目录、返回上级、点击路径导航，并选择当前目录。不再提供手动地址输入。

最近使用的目录保存在当前 WebUI 宿主的本地存储中，最多记住 8 个，页面显示最近 4 个。换宿主、清除宿主数据可能清除这份界面历史。

范围仍为主用户内部共享存储，支持 `/sdcard` 别名。排除 Android、隐藏目录和符号链接，不扩大到系统分区、其他用户存储或外置卡。回收站使用专门的目录读写逻辑，不受扫描规则误拦截，也不会被扫描或修复。

## 查重与保留建议

- 先按文件大小筛选，再完整读取同大小候选文件计算 SHA-256；摘要相同才归组。清理前再次校验待处理文件及保留文件。
- 同名并不代表重复，异名也可以判为重复。不是图片相似度、音频听感或视频相似内容识别；重新编码后的媒体通常不算相同文件。
- 默认排除空文件，可设置最小大小；每次最多枚举 20 万个文件。读取失败、扫描期间变化的文件会跳过并计数。
- 当同组同时存在 `文件1.m4a` 与 `文件1(1).m4a`，优先建议保留前者，支持空格和中文括号形式。只有存在对应无编号名称时才按编号副本处理；否则按名称简洁程度、路径稳定排序。
- 页面显示建议原因。文件名不能证明真实来源，用户可以取消一份文件的勾选再勾选另一份，从而手动更换保留项。每组始终至少保留一份。
- 结果每页 25 组，每组最多展示前 100 份。“仅本页”针对该页各组的建议副本，包括同组未显示的文件。每组始终留一份；整组选取状态包含未显示的副本。

## 跨页选择与批量清理

重复文件和文件修复提供“仅本页”“全选”，回收站仅提供“全选”批量按钮，同时保留逐项勾选。

- 未选或部分选中时点击：补齐对应范围的建议项；重复组至少保留一份，修复跳过冲突项。
- 对应范围全部选中时按钮颜色加深并显示勾号，再次点击清除该范围；部分选中显示浅色和横线。
- 重复文件“全选”是选取全部建议副本，不会把每组所有文件同时选中。已有手动保留项会优先保留，不因补齐其他组而改变。
- 三个页面的选择均保存在模块内部，翻页和重新打开页面仍保留；底部显示跨页总数和容量。新扫描或新修复预览会重置对应旧选择。

点击“移入回收站”并确认后，处理的是所有页面已选文件。后台自动连续处理、分批保存进度，不再要求用户逐页点击，也不受原来的单次 500 项界面限制。可以离开页面后再查看状态，或请求停止；已经移动的文件保留在回收站，尚未处理的文件仍在原处。

清理过程中重新校验内容；保留文件或目标文件变化时跳过相应操作，结束时显示未完成数量和最多 100 条错误明细。检查点每 20 次成功移动保存；正常停止会保存最后进度。系统强制结束或断电可能留下尚未刷新的查重索引，回收记录在移动前保存，重新打开后应先核对回收站再重新扫描。

修复、回收站恢复及彻底删除同样自动连续处理全部所选，支持超过 500 项、进度和停止。停止只阻止后续处理，不会撤销已完成项。彻底删除无法通过模块恢复。执行确认显示跨页总数量与容量；如果其他页面改变了选择，执行会拒绝并要求重新确认。后台操作、扫描、修复和安装发布互斥。

## 回收站位置与迁移

统一路径：

```text
/storage/emulated/0/Android/FileManager/Trash/
├── files/<编号>/content    回收文件
└── records/<编号>.json   原路径、摘要、大小、时间等恢复记录
```

首次读取回收站或清理/恢复前，会检查目录是否能创建和读写，并尝试迁移旧版的：

- 文件：`/storage/emulated/0/.dupeguard-trash/`
- 记录：`/data/adb/dupeguard/trash/`

迁移逐项复制并校验内容及大小，保存新恢复记录后才删除对应旧文件和旧记录；中断后可以重试。需要临时复制空间。冲突、内容变化或路径不可用时，保留旧数据并明确报错。缺少恢复记录的旧文件不会被擅自删除。

扫描索引、跨页选择、修复历史及安装日志仍保存在 `/data/adb/dupeguard/`，本次只迁移回收文件与恢复记录。不要手工编辑、改名或移动回收文件及记录；此处不是加密保险箱，记录被其他工具破坏可能导致无法恢复原位置。

回收站页面显示位置、总数量和占用容量，每页 50 项。“全选”覆盖全部页面；再次点击取消全部。逐项修改后按钮显示部分选中。恢复和彻底删除处理所有页面所选，翻页不清除勾选。

**移入回收站仍占空间，彻底删除后才释放；不自动清空，卸载模块会彻底删除回收文件、恢复记录和私有历史。** 恢复不覆盖同名文件，要求原目录仍存在且有足够复制空间。新版回收记录会保留文件修改时间；旧版记录若不含该字段，无法据此补回日期。恢复后重新扫描。

## 文件修复

- 从文件名提取唯一的 `YYYY-MM-DD HH-mm-ss` 或 `YYYY-MM-DD_HH-mm-ss`，修正文件修改时间。默认北京时间，可选择其他提供的时区；有效年份范围 1970–2099。
- `微信 中华 2025-02-12 14-40-15.m4a` 的修改时间可设为北京时间 `2025-02-12 14:40:15`。
- 仅将结尾 `.m4a.aac` 改成 `.aac`（忽略大小写），不改变音频内容，不做格式转换。
- 两项可以单独或同时执行，先预览再确认；无效日期、多日期、同名冲突及文件变化会提示或跳过，不覆盖已有文件。
- 不修改创建时间、音频内嵌日期或应用缓存日期。修复记录仍存放在 `/data/adb/dupeguard/repairs/`。修复后重新查重。

## 外观

本版采用系统设置式卡片与底部导航，包含重复文件、文件修复、回收站和设置四页。目录选择与操作确认使用底部弹出面板，保留跨页选择、数量/容量确认、停止和错误提示。

设置页提供六种强调色、浅色/深色/纯黑/跟随系统、宿主 Monet、顶栏和底栏模糊、悬浮底栏、悬浮底栏玻璃效果及 90%–120% 界面缩放。关闭悬浮底栏时玻璃开关暂不可用，原偏好保留。减少动态效果的系统偏好会关闭装饰动画。

Monet 读取宿主实际提供的颜色；宿主未提供时明确提示并回退至保存的手动配色。成功读取时颜色和明暗随宿主，关闭后恢复手动偏好。模糊与玻璃效果受 WebView 支持程度影响。

所有偏好保存在当前宿主本地存储，清除宿主数据后会恢复默认。界面为本项目独立实现，参考了用户提供模块的布局风格，没有引入其设备操作功能或打包其代码。

### 卸载补充

KernelSU 实际执行卸载脚本的时机由管理器决定，不能将“点击卸载”视为清理已经完成。共享存储未解锁时，会将清理助手暂存到私有目录并后台等待，最多等待约 30 分钟；解锁后继续清理，成功时连助手本身一并删除。等待超时、权限不足或异常操作锁时保留未完成的数据并输出错误，日志为 `/data/adb/dupeguard/uninstall-cleanup.log`。等待期间重新安装会变更安装标识，使旧清理任务停止。

不会删除 Downloads、录音原目录、其他模块或宿主应用数据；WebUI 宿主自己隔离保存的网页缓存/偏好由宿主管理，不会为了清理本模块而清空整个宿主。旧版没有卸载脚本，须先升级本版才具备此清理功能。

参考：[KernelSU 卸载实现](https://github.com/tiann/KernelSU/blob/main/userspace/ksud/src/module.rs)、[Android CE 存储准备标志](https://android.googlesource.com/platform/frameworks/base/+/android16-release/services/core/java/com/android/server/pm/UserDataPreparer.java)。
